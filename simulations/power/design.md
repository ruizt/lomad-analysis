# Power Study Design

## Objective

Characterise the power of the CLT-based test as a function of *realized local separation* δ_t, across three trend structures (fixed-rate, stochastic repulsion, stochastic crossing) and key nuisance factors (SNR, autocorrelation, window size).

The null is **local affine similarity**, not trend identity: ν₂ₜ = a_t + b_tν₁ₜ with the coefficients drifting slowly enough to be near constant within any window, but free to accumulate across the series. Two series that are locally affine-related everywhere satisfy H₀ no matter how different their levels and scales become. That is the property the method claims, so it is the property the study has to simulate.

## Data-generating process

Series are generated via the trend + noise model

```         
X_{kt} = ν_{kt} + Z_{kt},   Z_{kt} ~ AR(1, φ, σ²),   k = 1, 2
```

where ν₁, ν₂ are generated by one of three trend structures and then passed through the affine layer, ν₂ ← a_t + b_tν₂ (see paper §Simulation / Trend construction).

## Trend structures

| Label | Generator                     | Key parameter       |
|-------|-------------------------------|---------------------|
| `fr`  | `sim_trends(method = "fr")`   | rate *r* = 0.01, `bump = "gaussian"` |
| `rs`  | `sim_trends(method = "rs")`   | bandwidth *bw* = 50 |
| `rm`  | `sim_trends(method = "rm")`   | bandwidth *bw* = 50 |

## Parameters

| Parameter              | Value                        |
|------------------------|------------------------------|
| Correlation window *s* | 50, 100, 150                 |
| Series length *T*      | 25*s* — i.e. 1250, 2500, 3750 |
| AR(1) coefficient *φ*  | 0.3, 0.5, 0.7                |
| Target SNR *λ*         | 0.5, 1.5                     |
| Smoothing window *h*   | 5                            |
| Fourier basis *nb*     | 151                          |
| Affine cap / bandwidth | 1.5% per window / 0.5*T*     |
| *d* grid               | per structure, see below     |
| Trend structures       | rs, rm, fr                   |

**The window is the design factor, not the series length.** *T* follows as 25*s*.
Accumulated affine drift depends on the number of windows *T*/*s*, so holding
that ratio fixed keeps the drift identical across cells (*b* swings about 17%
end to end at every *s*) instead of confounding window size with how much
affine variation the method faced. *nb* = 151 holds the shortest basis period
at *s*/3 for every *s*, so trend smoothness relative to the window is fixed too.

**Why the series are long.** The affine cap is per window — that is what keeps
the pair locally affine similar. A cap large enough to be visible within one
window breaks H₀. Length is what lets a small per-window drift accumulate into
genuinely different transformations at distant points in the series. At
*T*/*s* = 4, as in the previous design, the same cap reaches only 3%, which is
not a meaningfully different transformation. Power at matched separation does
not depend on *T*, checked directly across 400/1000/2500.

**The *d* grid is per structure.**

| structure | *d* values      |
|-----------|-----------------|
| `rs`      | 0, 0.60, 1.55   |
| `rm`      | 0, 0.36, 0.93   |
| `fr`      | 0, 0.27, 0.70   |

*d* is a generator knob, not an effect size. The same *d* produces roughly 2×
different local separation across structures because they distribute it
differently in time, so it is scaled onto a common realized δ_t (median ≈ 0,
0.20, 0.45) and never appears in a figure. The factors are 1.00 / 0.60 / 0.45
against a shared base grid; because separation is linear in *d*, one constant
per structure suffices. See `_notes/delta-calibration.md`.

Three values are enough. A single *d* already spans most of the δ_t range
(q10 0.036 to q90 0.747 at `rs`, *d* = 0.60), so the grid shifts the
distribution rather than creating the coverage; a fourth and fifth value move
bin occupancy by about a percentage point.

**Pulse shape for `rate`.** The events use a gaussian pulse rather than a
shape-2 gamma. The gamma leaves zero with non-zero slope,
so the coupling weight has a corner at each event onset, and difference-based
noise estimation cannot cancel a corner — Hall and Van Keilegom (2003, eqn 2.4)
require a bounded derivative. What survives differencing enters the residual
autocovariance as a positive additive bias, which is then amplified near the
unit root, since the long-run noise variance goes as (1+φ)/(1−φ) with
sensitivity 2/(1−φ)² — about 22 at φ = 0.7 against 4 at φ = 0.3. Under the
gamma pulse this cost the fixed-rate structure almost all detection at high φ
and drove its localization concordance below chance. The gaussian pulse is
matched on width and smooth at onset; `fr` remains the weakest structure at
high autocorrelation, which is the contrast it is in the design to provide,
without the anomaly dominating the figures.

| Replicates *S*         | 20 (local) → 500 (Tide)    |
| Significance level *α* | 0.05                       |

## Estimands

The estimand is **local**: rejection probability as a function of realized
separation, P(reject window *t* | δ_t). Global "did anything fire" power is not
reported — with 1200 to 3600 windows per series it saturates immediately, and
the sup-null it corresponds to is not the hypothesis the paper states.

δ_t = √(1 − r_t²) is measured on the noise-free trends, smoothed exactly as the
observed series are, by least squares within each window. The generating
coefficients are deliberately *not* used to remove the affine map: fixing the
slope at its window average charges the base separation twice once *d* > 0, and
δ_t then exceeds 1.

For each replicate, `run_rep()` returns two components:

### Summary (one row per replicate)

- **detected**: did any window get flagged (kept for reference, not reported)
- **n_win**: number of testable windows
- **delta_med**: median realized δ_t
- **lambda1**, **lambda2**: realized per-series SNR on Proposition 1's definition
- **b_range**: realized affine drift, so the layer's magnitude is recoverable

### Windows (the unit of analysis)

One row per retained window, per replicate:

- **t**: time index
- **delta**: ground-truth δ_t
- **lambda**: min(λ₁, λ₂) local SNR
- **p_raw**: raw p-value, so the study can be rethresholded at another α
- **rejected**: BY decision at α = 0.05

Every window is stored. Records are highly redundant — windows overlap by
*s* − 1 points, and a series of 25*s* holds only about 25 non-overlapping ones —
but subsampling them costs no run time and only saves disk, so the volume is
sized to hold them all (~4.5 GB) rather than discarding adjacency information
that later analyses might want.

## Why φ tops out at 0.7

The upper φ cell used to be 0.8, with an oracle arm alongside it that bypassed
noise estimation using the true AR(1) parameters. That arm existed because at
φ = 0.8 the MA smoother cannot track the trend, leaving trend signal in the
residuals; the AR estimator absorbs the leakage as inflated φ̂, and the test goes
conservative. Measured at the current geometry, φ̂ pegs at its 0.99 clamp in 8%
of `rs` replicates and 17–67% of `fr` ones, and `fr` loses **all** detection
(rejection rate 0.000 at both SNRs).

At φ = 0.7 that disappears: φ̂ has a median of 0.733 for `rs` with no pegging at
all, `fr` recovers to a non-zero rejection rate, and 0.3 / 0.5 / 0.7 is evenly
spaced. The oracle arm was diagnosing a pathology that the design no longer
walks into, so it is gone — halving the job count.

## Expected outputs

### Per job (Tide) or per combo (local)

- `{cell}.rds` — metadata + per-replicate summary data frame
- `{cell}-windows.rds` — per-window (δ_t, λ, p_raw, rejected)

### Aggregated (after `collect-results.R`)

- `results/simulations-power-results.rds` — every replicate, every cell
- `results/simulations-power-curves.rds` — rejection rate by δ_t bin: the local power curves
- `results/simulations-power-auc.rds` — concordance between rejection and δ_t

Both aggregates pool over *d*, which is a nuisance knob whose only job is to
populate the δ_t range. `localization-sweep.R` is gone: it existed to recover
(δ_t, rejected) pairs by rereading full-length series files, and `sim.R` now
emits them directly.

### Figures

Built by `simulations/simulation-results.R`, not by this study, and written to
`simulations/_img/`: `fig-power.png` and `fig-localization.png`.

## File layout

```         
power/
├── design.md           ← you are here
├── simulation-template.R          ← local illustration mirroring tide/sim.R; writes nothing
├── collect-results.R    ← assembles fetched per-cell files into the compiled artifacts
├── results/
│   ├── simulations-power-results.rds       ← tracked
│   ├── simulations-power-curves.rds        ← tracked
│   ├── simulations-power-auc.rds           ← tracked
│   ├── _simulations-power.zip              ← archive of _raw/, Zenodo only
│   └── _raw/           ← per-cell .rds + -windows.rds fetched from Tide, Zenodo only
└── tide/               ← Kubernetes scaffolding
    ├── sim.R           ← simulation script (mounted into container)
    ├── submit.sh       ← runs the full pipeline (PVC → jobs → wait → fetch)
    ├── submit_sweep.sh ← submits one Job per (struct, d, s, phi, snr)
    ├── pvc.yaml        ← shared storage (create once)
    ├── job.yaml        ← Job spec template, filled by envsubst (single source of truth)
    ├── accessor.yaml   ← lightweight pod for file retrieval
    ├── fetch.sh        ← copies results from PVC to local machine
    └── test_one_job.sh ← submits one small job to smoke-test sim.R
```

`_`-prefixed entries are gitignored and archived on Zenodo; the compiled `.rds`
files are small enough to track, so a fresh clone can rebuild every figure
without downloading anything.

`tide/` holds everything that talks to the cluster. `collect-results.R` and
`localization-sweep.R` sit outside it because they only read local files.
`job.yaml` is the one copy of the Job spec: `submit_sweep.sh` and
`test_one_job.sh` fill its placeholders with `envsubst`, so the spec cannot
drift between the sweep and the smoke test.

## Workflow

### Local development

Source `simulation-template.R` in RStudio. It loops over all (struct, d, n, phi, snr) combinations with *S* = 20 replicates and computes detection rates in memory. It deliberately writes nothing — only `tide/sim.R` (on the cluster) and `collect-results.R` write into `results/`. To watch the method work on a single replicate under each trend structure, see the *Simulating your own scenarios* section of the package vignette (`vignette("lomad")`), which is where that walkthrough now lives.

To inspect a single replicate interactively:

``` r
source("simulations/power/simulation-template.R")
run_rep(d = 1.0, struct = "smooth", n = 500, phi = 0.5, snr = 1.5, seed = 12345)
```

Post-hoc evaluation of the stored series data — how well rejections align with the true local separation, swept over the threshold that defines a decoupled window — is done by `localization-sweep.R`, whose output feeds the localization figure.

### Shared container image

All studies share a single Docker image that is pre-built and publicly available:

```         
ghcr.io/ruizt/lomad-simulations:latest
```

The image contains R and all packages (including lomad) but no simulation scripts — `sim.R` is mounted into the container via a Kubernetes ConfigMap. See `../README.md` for build/update instructions.

### Running on Tide

#### One-shot pipeline

``` bash
bash simulations/power/tide/submit.sh
```

This creates the PVC, submits one job per parameter combination, polls until all complete, and fetches results to `results/_raw/`.

#### Step-by-step

``` bash
# 1. Create PVC (once)
kubectl apply -n cal-poly-ruiz -f simulations/power/tide/pvc.yaml

# 2. Submit all parameter combinations (creates ConfigMap + Jobs)
bash simulations/power/tide/submit_sweep.sh

# 3. Monitor
kubectl get jobs -n cal-poly-ruiz -l app=lomad-power

# 4. Fetch results
bash simulations/power/tide/fetch.sh

# 5. Assemble results from per-job files
Rscript simulations/power/collect-results.R

# 6. Summarise and plot (local post-processing)
Rscript simulations/power/localization-sweep.R   # optional: localization
Rscript simulations/simulation-results.R        # all paper figures

# 7. Clean up
kubectl delete jobs -n cal-poly-ruiz -l app=lomad-power
kubectl delete -n cal-poly-ruiz -f simulations/power/tide/pvc.yaml
```

#### Tips

- Start with `SIM_S=20` to confirm everything works end-to-end.
- Each parameter combination runs as a separate job. Jobs run in parallel on the cluster.
- If you update `sim.R`, re-running `submit_sweep.sh` updates the ConfigMap automatically — no image rebuild needed.
- `collect-results.R` assembles per-job `.rds` files into `results/simulations-power-results.rds` and a detection summary. Figures are built separately by `simulations/simulation-results.R`, which writes to `simulations/_img/`.
- Series files (`-series.rds`) are fetched alongside the summary files and consumed by `localization-sweep.R`, which is kept separate from `collect-results.R` because it reads ~1.4 GB and takes minutes.
