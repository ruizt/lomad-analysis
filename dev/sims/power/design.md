# Power Study Design

## Objective

Characterise the power of the CLT-based test as a function of separation *d* across three trend structures (event-rate, stochastic repulsion, stochastic crossing) and key nuisance factors (SNR, autocorrelation, series length).

## Data-generating process

Series are generated via the trend + noise model

```         
X_{kt} = ν_{kt} + Z_{kt},   Z_{kt} ~ AR(1, φ, σ²),   k = 1, 2
```

where ν₁, ν₂ are generated by one of four trend structures at a controlled L² separation *d* (see paper §Simulation / Trend construction).

## Trend structures

| Label    | Generator                       | Key parameter       |
|----------|---------------------------------|---------------------|
| `rate`   | `sim_trends(method = "rate")`   | rate *r* = 0.01     |
| `smooth` | `sim_trends(method = "smooth")` | bandwidth *bw* = 50 |
| `cross`  | `sim_trends(method = "cross")`  | bandwidth *bw* = 50 |

## Parameters

| Parameter              | Value                      |
|------------------------|----------------------------|
| Series length *T*      | 200, 400, 600              |
| AR(1) coefficient *φ*  | 0.3, 0.5, 0.8              |
| Target SNR *λ*         | 0.5, 1.5                   |
| Smoothing window *h*   | max(5, floor(T/200))       |
| Correlation window *s* | min(60h, floor(T/4))       |
| *d* grid               | 0, 0.25, 0.5, 0.75, 1, 1.5 |
| Trend structures       | smooth, cross, rate        |
| Replicates *S*         | 20 (local) → 500 (Tide)    |
| Significance level *α* | 0.05                       |

## Estimands

For each replicate, `run_rep()` returns two components:

### Summary (one row per replicate)

- **detected**: indicator — did any time point get flagged?

Detection rate (mean of `detected` across replicates) is the primary power metric.

### Series (stored per replicate for downstream analysis)

- **w**: coupling weight vector from `sim_trends()` (NULL for `dist`)
- **vi**: valid indices from `lomad_fit()`
- **p_raw**: raw p-values from `lomad_test()`
- **p_adj**: BY-adjusted p-values
- **rejected**: logical rejection vector

The series data supports future localization analysis (e.g., evaluating how precisely the test delineates divergent regions). 

## Oracle comparison

At high autocorrelation (φ = 0.8), the MA smoother cannot fully track the trend, leaving trend signal in the noise residuals. The AR estimator absorbs this leakage as inflated φ̂, making the test overly conservative and causing power to *decrease* with *d*. The effect is amplified at high SNR (where trend leakage is large relative to noise).

To isolate this as an estimation problem rather than a test problem, `sim.R` supports an oracle mode (`SIM_ORACLE=TRUE`) that bypasses noise estimation and uses the true AR(1) parameters. The oracle sweep runs for φ = 0.8 only (30 jobs) and produces files with an `-oracle` suffix (e.g., `smooth_d1-0_n600_snr1-5_phi0-8-oracle.rds`).

`collect.R` combines oracle and estimated results with a `method` column, and the power curve plots overlay both as solid (estimated) vs dashed (oracle) lines.

## Expected outputs

### Per job (Tide) or per combo (local)

- `{combo}.rds` — metadata + per-replicate summary data frame
- `{combo}-series.rds` — list keyed by seed with series-level data

### Aggregated (after `collect.R`)

- `results/results.rds` — all replicates, all parameter combinations
- `results/results_summary.rds` — detection rate by (struct, d, n, phi, snr, method)
- `results/power_curves_n{N}.png` — detection rate vs *d*, faceted by snr × phi

## Workflow

### Local development

Source `template.R` in RStudio. It loops over all (struct, d, n, phi, snr) combinations with *S* = 20 replicates, computes detection rates, and saves results to `results/`. See `settings.R` for a visual walkthrough of single replicates at each structure.

To inspect a single replicate interactively:

``` r
source("dev/sims/power/template.R")
run_rep(d = 1.0, struct = "smooth", n = 500, phi = 0.5, snr = 1.5, seed = 12345)
```

The `calibrate_threshold()` function in `template.R` supports post-hoc evaluation of sensitivity, specificity, and FDR at any *w* threshold from the stored series data.

### Shared container image

All studies share a single Docker image that is pre-built and publicly available:

```         
ghcr.io/ruizt/lomad-sims:latest
```

The image contains R and all packages (including lomad) but no simulation scripts — `sim.R` is mounted into the container via a Kubernetes ConfigMap. See `../tide-example/building-containers.md` for build/update instructions.

### Running on Tide

#### One-shot pipeline

``` bash
bash dev/sims/power/tide/submit.sh
```

This creates the PVC, submits one job per parameter combination, polls until all complete, and fetches results to `results/raw/`.

#### Step-by-step

``` bash
# 1. Create PVC (once)
kubectl apply -n cal-poly-ruiz -f dev/sims/power/tide/pvc.yaml

# 2. Submit all parameter combinations (creates ConfigMap + Jobs)
bash dev/sims/power/tide/submit_sweep.sh

# 3. Monitor
kubectl get jobs -n cal-poly-ruiz -l app=lomad-power

# 4. Fetch results
bash dev/sims/power/tide/fetch.sh

# 5. Assemble results from per-job files
Rscript dev/sims/power/tide/collect.R

# 6. Summarise and plot (local post-processing)
Rscript dev/sims/power/postprocess.R

# 7. Clean up
kubectl delete jobs -n cal-poly-ruiz -l app=lomad-power
kubectl delete -n cal-poly-ruiz -f dev/sims/power/tide/pvc.yaml
```

#### Tips

- Start with `SIM_S=20` to confirm everything works end-to-end.
- Each parameter combination runs as a separate job. Jobs run in parallel on the cluster.
- If you update `sim.R`, re-running `submit_sweep.sh` updates the ConfigMap automatically — no image rebuild needed.
- `collect.R` assembles per-job `.rds` files into `results/results.rds`. `postprocess.R` reads that file, computes summaries, and writes power curve plots to `results/_img/`.
- Series files (`-series.rds`) are fetched alongside summary files but are not consumed by either script. Use them for localization analysis or threshold calibration.
